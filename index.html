📌 Visão Geral do Exame AZ-900

▼

O exame AZ-900: Microsoft Azure Fundamentals é a porta de entrada para o ecossistema de nuvem da Microsoft. Ele valida conhecimentos fundamentais sobre conceitos de nuvem, serviços do Azure, segurança, privacidade e gerenciamento de custos.

Detalhes da Prova:
  • Duração: ~45 a 60 minutos (30 a 40 questões).
  • Nota de Corte: 700 de 1000 pontos (70%).
  • Formato: Múltipla escolha, resposta única, associação e verdadeiro/falso.
  • Perfil do Candidato: Profissionais de TI, Gestores e Engenheiros de Dados/BI que buscam consolidar conceitos de nuvem pública.

☁️ Domínio 1: Conceitos de Nuvem (25–30%)

▼

1.1 Modelos de Nuvem

  • Nuvem Pública: Propriedade de provedores de terceiros (como a Microsoft). Recursos compartilhados via internet. Sem custo de capital inicial.
  • Nuvem Privada: Infraestrutura dedicada exclusivamente a uma única organização. Maior controle sobre a segurança e conformidade.
  • Nuvem Híbrida: Combina nuvem pública e privada, permitindo que dados e aplicativos sejam compartilhados entre elas.

1.2 Modelos de Serviço de Nuvem (SPI)

  • IaaS (Infrastructure as a Service): Aluguel de infraestrutura de TI (VMs, redes, armazenamento). Maior controle e responsabilidade do usuário (Patching do SO, configurações). Ex: Azure VMs.
  • PaaS (Platform as a Service): Ambiente para desenvolvimento e implantação de apps sem gerenciar servidores subjacentes. A Microsoft cuida do SO e runtime. Ex: Azure App Service, Azure SQL Database.
  • SaaS (Software as a Service): Aplicação completa entregue pela internet. Ex: Microsoft 365, Power BI Service.
Modelo de Responsabilidade Compartilhada:

Na IaaS, você gerencia o SO e as aplicações. Na PaaS, você gerencia apenas os dados e a aplicação. Na SaaS, você gerencia apenas os dados e os acessos de usuários. A Microsoft sempre gerencia a segurança física do datacenter.

1.3 Benefícios da Nuvem

  • Alta Disponibilidade: Garantia de tempo de atividade (SLAs).
  • Escalabilidade: Aumento de capacidade (Vertical: mais RAM/CPU; Horizontal: mais instâncias/VMs).
  • Elasticidade: Ajuste automático de recursos com base na demanda (Auto-scaling).
  • Agilidade: Implantação rápida de recursos.
  • CapEx vs. OpEx: CapEx (Despesas de Capital - investimento inicial em hardware) vs. OpEx (Despesas Operacionais - pague pelo que usar/subscrição).

🏗️ Domínio 2: Arquitetura e Serviços Azure (35–40%)

▼

2.1 Componentes de Arquitetura do Azure

  • Regiões: Áreas geográficas contendo um ou mais datacenters conectados por rede de alta velocidade. Ex: Brazil South (São Paulo), East US.
  • Zonas de Disponibilidade (Availability Zones): Datacenters fisicamente separados dentro da mesma região, isolados contra falhas de energia/rede.
  • Grupos de Recursos (Resource Groups): Recipientes lógicos para agrupar recursos do Azure que compartilham o mesmo ciclo de vida.
  • Assinaturas (Subscriptions): Unidade de cobrança e gerenciamento de acesso.

2.2 Principais Serviços de Computação e Rede

  • Azure Virtual Machines (VMs): Computação IaaS sob demanda.
  • Azure App Service: Serviço PaaS para hospedagem de aplicações web e APIs.
  • Containers (ACI e AKS): Azure Container Instances (execução rápida de contêineres) e Azure Kubernetes Service (orquestração de microsserviços).
  • Virtual Network (VNet): Rede privada isolada no Azure.
  • Azure ExpressRoute: Conexão privada dedicada entre a infraestrutura on-premises e o Azure (não passa pela internet pública).

2.3 Armazenamento e Banco de Dados

  • Azure Blob Storage: Armazenamento de dados não estruturados (arquivos, imagens, vídeos, backups). Tem camadas: Hot, Cool, Cold e Archive.
  • Azure Files: Compartilhamento de arquivos gerenciado via protocolo SMB/NFS.
  • Azure SQL Database: Banco de dados relacional PaaS gerenciado baseado em SQL Server.
  • Azure Cosmos DB: Banco de dados NoSQL globalmente distribuído e de ultra-baixa latência.
  • Azure Synapse Analytics: Serviço de data warehousing e análise de Big Data em escala empresarial.

🔒 Domínio 3: Gestão, Governança e Segurança (30–35%)

▼

3.1 Segurança e Identidade

  • Microsoft Entra ID (antigo Azure Active Directory): Serviço de gerenciamento de identidade e acesso baseado em nuvem.
  • MFA (Autenticação Multifator): Exige dois ou mais elementos de verificação para acesso.
  • RBAC (Role-Based Access Control): Concede permissões com base no papel do usuário (Princípio do Menor Privilégio). Ex: Reader, Contributor, Owner.
  • Zero Trust: Modelo de segurança que assume violação e verifica explicitamente cada solicitação de acesso.

3.2 Governança e Conformidade

  • Azure Policy: Impõe regras e padrões aos recursos (ex: proibir a criação de VMs em determinadas regiões).
  • Resource Locks: Impede a exclusão ou alteração acidental de recursos críticos (CanNotDelete, ReadOnly).
  • Azure Tags: Metadados no formato Chave:Valor aplicados a recursos para organização e controle de custos.

3.3 Gerenciamento de Custos

  • Calculadora de TCO (Total Cost of Ownership): Compara os custos de manter infraestrutura On-Premises vs. Migrar para o Azure.
  • Azure Pricing Calculator: Estima os custos mensais previstos para recursos no Azure.
  • Azure Cost Management: Monitora, analisa e otimiza os gastos com os serviços ativos.
